## Interaction Contract

This phase is primarily behavioral (streaming + Wake Lock), not a new visual design phase. The following interaction contracts govern implementation.

### Loading Overlay Behavior

| State | Trigger | Visual |
|-------|---------|--------|
| Overlay shown | Reading view mounts with params in sessionStorage | Full-screen `LoadingOverlay` with moon/stars breathing animation |
| Overlay dismissed | First complete paragraph arrives from stream | Overlay removed, first paragraph visible with fade-in |
| Overlay shown (no params) | Reading view mounts without sessionStorage params | "No story yet" empty state (not loading overlay) |

Source: CONTEXT.md D-03, RESEARCH.md Pitfall 3.

### Paragraph Streaming Reveal

| Property | Value | Source |
|----------|-------|--------|
| Reveal unit | Complete paragraph (buffered to `\n\n` boundary) | CONTEXT.md D-06, D-08 |
| Animation | `paragraphFadeIn` keyframe: opacity 0 to 1, translateY 4px to 0 | CONTEXT.md D-07 |
| Duration | 300ms | CONTEXT.md specifics (prefer shorter) |
| Easing | ease-out | Claude's discretion |
| Partial paragraph | Never rendered mid-stream | CONTEXT.md D-08 |

**New keyframe to add to reading view:**

```css
@keyframes paragraphFadeIn {
  from { opacity: 0; transform: translateY(4px); }
  to { opacity: 1; transform: translateY(0); }
}
```

Each paragraph element receives `animation: paragraphFadeIn 300ms ease-out forwards` on render.

### Scroll Progress Bar

| Property | Value |
|----------|-------|
| Position | Fixed, top-left |
| Height | 3px |
| Color | `--color-secondary-container` (#fcd400) |
| Behavior during streaming | Grows as paragraphs accumulate; tracks scroll position |
| z-index | 40 |

No changes from existing implementation.

### Stream Completion States

| State | Visual | Copy |
|-------|--------|------|
| Streaming in progress | Paragraphs accumulating, no end-of-story button | No indicator needed (paragraphs appearing IS the indicator) |
| Stream complete | "NEW STORY" button fades in below last paragraph | Button copy: "NEW STORY" (existing) |
| Mid-stream error | Gentle message below last rendered paragraph + retry button | See Copywriting Contract below |

### Wake Lock Behavior

| Event | Action | Source |
|-------|--------|--------|
| Reading view mounts | Acquire `navigator.wakeLock.request('screen')` | CONTEXT.md D-09 |
| Reading view unmounts | Release via `sentinel.release()` | CONTEXT.md D-10 |
| API unsupported | `console.warn()`, continue normally | CONTEXT.md D-11 |
| Request denied | `console.warn()`, continue normally | CONTEXT.md D-11 |

No visual indicator for Wake Lock status. Silent feature.

## Accessibility Notes

- Loading overlay uses `role="alert"` and `aria-live="polite"` (existing pattern, preserved)
- Scroll progress bar uses `aria-hidden="true"` (existing pattern, preserved)
- "CREATE A STORY" link has `aria-label="Create a new bedtime story"` (existing pattern, preserved)
- Wake Lock failure is silent -- no user-facing error for an invisible feature
- Streaming paragraphs use semantic `<p>` elements within `<article>` (existing pattern, preserved)
- Mid-stream error retry button must be keyboard-focusable and have clear focus-visible styling matching existing button pattern
